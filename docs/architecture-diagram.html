FFmpeg Editor

Local Video Editing Application — Architecture & Workflow Diagram

System Architecture

🎨
Frontend (apps/web)
Next.js 15 + Turbopack
  • Component VideoPlayer — Main video preview & playback
  • Component VideoUploader — File drag & drop upload
  • Component Sidebar — Export settings & controls
  • Component Timeline — Trim range visualization
  • Component CropOverlay — Visual crop selection
  • Hook useVideoMetadataMutation — Fetch video info via ffprobe
  • Hook useTranscodeMutation — Submit export job (SSE)
  • Store useVideoStore — TanStack Store (client state)
⚡
Backend (apps/api)
Hono + Bun Runtime
  • Route GET /health — Server health check
  • Route POST /api/metadata — ffprobe video analysis
  • Route POST /api/transcode — Start export job
  • Route GET /api/transcode/progress/:id — SSE progress stream
  • Util ffmpegBuilder.ts — Build FFmpeg CLI arguments
📦
Shared Packages (packages/)
Monorepo Workspace
  • Config @repo/config — TypeScript configuration
  • Config @repo/ui — Shadcn UI components (12+ components)
  • Config Turborepo — Task orchestration & caching
🔧
External Tools & Libraries
Runtime Dependencies
  • CLI Tool ffmpeg — Video transcoding engine
  • CLI Tool ffprobe — Video metadata extraction
  • Runtime Bun v1.3.14 — JavaScript runtime & package manager
Data Flow Connections:
→ Browser → POST /api/metadata (FormData) → ffprobe analysis
→ Browser → POST /api/transcode (FormData) → FFmpeg export job
→ Browser ← GET /api/transcode/progress/:id (SSE) ← FFmpeg progress pipe
→ FFmpeg → ~/ffmpego_edits/ or /mnt/d/ffmpego_edits/ (output directory)

User Workflow

1
Upload Video File
User drags and drops or selects a video file to upload.
Client Action
VideoUploader.tsx receives File object
State Update
useVideoStore.file = File, mediaUrl = URL.createObjectURL()
2
Fetch Video Metadata (ffprobe)
Client sends video file to backend for analysis via ffprobe.
API Call
POST /api/metadata (FormData)
Backend Process
Bun.spawn(['ffprobe', ...args]) → JSON parse
Data Extracted
Duration, Resolution, Codec, FPS, Bitrate
Client State
sourceWidth, sourceHeight, duration, videoCodec, etc.
3
Video Editing & Configuration
User configures trim range, crop area, and export settings via the UI.
Timeline Component
Set trimRange: [start, end]
CropOverlay Component
Set crop: {x, y, width, height} in percentages
Sidebar Settings
Format (mp4/webm/mov), Quality, FPS, Speed
4
Submit Export Job
Client sends video file + export settings to backend for processing.
API Call
POST /api/transcode (FormData)
Backend Process
Write file to os.tmpdir(), build FFmpeg args via ffmpegBuilder.ts
FFmpeg Command Built
-ss -to -i -c:v -vf crop,setpts ... -progress pipe:2
5
Stream Export Progress (SSE)
Backend streams real-time progress updates to the client via Server-Sent Events.
Client Connection
new EventSource(progressUrl) — listens for events
FFmpeg Progress Parsing
Read stderr: out_time_ms=XXXXX → calculate % of duration
SSE Stream
data: {"status":"processing","progress":45} (every 200ms)
6
Export Complete → File Saved
FFmpeg finishes encoding. Files are written to the output directory.
Output Path
/mnt/d/ffmpego_edits/{filename}.{format}
Alternative Output (speed-adjusted)
{filename}_{speed}.{format} (if speed ≠ 1)
Client State Update
transcodeStatus: "completed", transcodeProgress: 100

Key Architecture Decisions

Monorepo Architecture
Turborepo manages apps/web, apps/api, and packages/* with shared build cache.
Bun Runtime
Both frontend (Turbopack) and backend (Hono) run on Bun for performance.
TanStack Store
Client-side UI state managed via TanStack Store (not Redux/Zustand).
SSE for Progress
Server-Sent Events stream FFmpeg progress without polling.
Local-Only Deployment
No auth, CORS, or rate limiting — optimized for local developer experience.
Shadcn UI Components
12+ pre-built components (Rhea style, Teal theme, Inter font).
